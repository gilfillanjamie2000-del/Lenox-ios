# Files Open regression — 2 November 2026

Mike reports that the public `4d7ce70794a3` test build allows selecting songs, including multiple selections, but its Files Open action cannot be tapped to finish. The prior native adapter checks did not exercise this system UI and do not establish a working phone import.

This continuation replaces SwiftUI's audio `fileImporter` with a stable `UIDocumentPickerViewController` hosted in a sheet. It uses open-in-place, keeps the original read-only reference/bookmark storage policy and allows generic provider-labelled items. Decoder validation now checks every selected file before a single atomic batch save. Non-audio, unreadable and oversized selections preserve the old library; validation never calls Play. Relink still selects only one file and validates it before replacing a reference. Cancel completes once with explicit feedback. The controller is not reconstructed when audio/scene state updates.

The app declares open-in-place support and shares only its Documents directory through Files. The private library and bookmarks remain in Application Support. Users may place songs in Files → On My iPhone → LENOX Test as another import location. No audio is copied automatically or modified, and no library reset or storage-schema migration is introduced.

Mike additionally requested removal of the 20-song limit and the audio-file-size cap. Both are removed from normal import, storage validation, individual/batch saves and playlist backup import/export. Large selections acquire, validate and bookmark one file at a time instead of retaining a security scope for every imported track; unloaded songs are reopened from bookmarks only when loaded. Validation opens `AVAudioFile` and decodes at most 4,096 frames, without creating a player or reading an entire recording. The library uses lazy rows. Tests cover a 2,000-track batch, a 501-track playlist save/export/import/reload, an actual sparse 128 MiB WAV import and 8 GiB metadata preservation. Physical storage, codec/engine capabilities and device memory still apply. Existing 4 MiB metadata and 100-playlist guards remain; they are not audio-file-size limits. The schema and saved data stay compatible.

Version 0.1.1, build 2 distinguishes this correction from the first test IPA. The deterministic project generator registers `AudioDocumentPicker.swift`. The package filename now comes from the built bundle's actual version/build values.

New native checks cover playable audio with a generic `.bin` label, whole-batch rejection of undecodable content, and no playback caused by validation. New UI scenarios must tap real Files rows, assert Open is enabled, press Open and verify the library result for single and multiple selections, cancellation and invalid content. Fixtures are generated WAVs in a Simulator-only Documents folder; the test does not invoke the picker delegate directly. Existing regressions remain mandatory. Native/CI results for this revision are pending until an exact-source receipt is recorded; real iPhone/provider acceptance remains required.

The failure artifact now retains any already-built unsigned IPA and exact source alongside reports, clearly under a diagnostics name. This preserves failed candidates without representing them as validated builds.
